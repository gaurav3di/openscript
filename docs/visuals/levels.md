# Levels, ranges and the price axis

By the end of this page you will be able to put horizontal reference lines in a
pane, compute those lines from the data instead of fixing them, pin a pane's
scale so it never rescales, and control what the price axis says.

A **level** is one horizontal line straight across the pane at one price. It
costs no plot slot, carries no column of values, and takes one call.

---

## What a level is, and what it is not

A plot draws a different value on every bar. A level draws one value across the
whole pane. That difference is not cosmetic: the two are different fields of the
chart contract and behave differently in ways that matter.

| | `level` | `plot` |
|---|---|---|
| What is drawn | One horizontal line across the pane | A column of one value per bar |
| Plot slot | None | One |
| Legend entry | No | Yes, with the current value |
| Settings style row | No | Yes, generated by the host |
| History | None. You see one line, not where it used to be | Retained per bar, readable with `[]` |
| Price | Evaluated every bar; the line drawn is the last executed bar's | Every bar's value is drawn at that bar |
| Can a `fill` name it | No | Yes |

The rule in the fifth and sixth rows is the one that catches people, and it gets
its own section below.

A level is the right call for a threshold that a reader needs to see the height
of everywhere on the pane: 70 and 30 on an oscillator, zero under a signed
histogram, yesterday's high on a price chart. It is the wrong call for anything
whose past positions are part of the picture.

---

## The call

```
level(price, title = "", color = gray, style = "dashed", width = 1)
```

| Argument | Type | Default | Means |
|---|---|---|---|
| `price` | `series number` | required | The price to draw the line at. `none` draws nothing |
| `title` | `string` | `""` | The label carried with the line |
| `color` | `color` | `gray` | The line colour |
| `style` | `string` | `"dashed"` | `"solid"`, `"dashed"` or `"dotted"` |
| `width` | `number` | `1` | Thickness |

`level` is top level only, like `plot` and `fill`. The set of levels is part of
the fixed shape of the study and has to exist before bar 0, so a level cannot be
wrapped in an `if`. To make one disappear, give it an absent price.

The default style is dashed rather than solid on purpose. A reference line is
not data. A solid line at 70 competes with the oscillator it is a reference for,
and a reader glancing at the pane has to decide which of the two lines is the
reading. A dashed line reads as scaffolding at any distance, which is what it
is.

---

## Fixed levels

The everyday case: a bounded oscillator with the two thresholds that define its
zones, and a pane whose scale is pinned so those thresholds sit at the same
height on every chart.

```
version 1

study("Stochastic", precision = 2, range = [0, 100])

len     = input(14, "Length",   min = 1, max = 200)
kSmooth = input(3,  "Smooth K", min = 1, max = 50)
dSmooth = input(3,  "Smooth D", min = 1, max = 50)

s = stoch(len, kSmooth, dSmooth)

// Declared before the plots, so the reference lines sit under the readings
// rather than over them.
level(80, "Overbought", fade(red, 40))
level(50, "Middle", fade(gray, 70), style = "dotted")
level(20, "Oversold", fade(lime, 40))

plot(s[0], "K", aqua,   width = 2)
plot(s[1], "D", orange, width = 2)
```

Three details are deliberate. The thresholds are faded, because they are
reference and the two readings are data. The midline is dotted rather than
dashed, one step further back again, because it is a reference for the
references. And the levels are declared above the plots, since declaration order
is the order the columns and lines are listed and is the cheapest control you
have over what covers what.

## Levels computed from the data

A level's price does not have to be a constant. It can be any expression, and it
is re-read on every bar.

```
version 1

study("Previous day range", overlay = true, precision = 2)

// The default mode is "confirmed", which reads only coarse bars that have
// closed, so these are yesterday's numbers and they never repaint.
dayHigh = req.timeframe("1D", high)
dayLow  = req.timeframe("1D", low)
dayMid  = (dayHigh + dayLow) / 2

level(dayHigh, "Previous day high", fade(aqua, 25),   width = 2)
level(dayMid,  "Previous day midpoint", fade(gray, 55), style = "dotted")
level(dayLow,  "Previous day low",  fade(orange, 25), width = 2)
```

Three lines, no plot slots, no columns retained, and they move to the new day's
numbers by themselves.

The specification chose to give a level a per-bar price rather than requiring a
compile-time constant, and the reason is exactly this script. Requiring a
constant would be simpler to implement and would make yesterday's high
impossible to draw as a level, which is one of the two things people most want a
level for.

### The rule that follows: the last bar wins

**A level's price is evaluated on every bar, and the line drawn is the one from
the last bar executed.**

Read that twice, because everything surprising about levels comes out of it.

A level has no history. There is one line, and its height is whatever the
expression produced on the most recent bar the engine ran. Scrolling back to
last month does not show you where the level was last month; it shows the same
line, at today's height.

Two consequences, and the fix for each.

**If the price is absent on the last bar, no line is drawn at all.** This turns
an obvious-looking script into a script that draws nothing:

```
// Draws nothing except on a session's first bar, and since only the last
// executed bar decides, it usually draws nothing at all.
level(session.isFirstBar ? open : none, "Session open", aqua)
```

The fix is to hold the value, which is what `var` is for:

```
version 1

study("Session open", overlay = true, precision = 2)

var sessionOpen = none

// Captured once per session and carried on every bar after it, so the level
// has a value to read on whichever bar turns out to be the last one.
if session.isFirstBar
    sessionOpen = open

level(sessionOpen, "Session open", fade(aqua, 25), style = "solid", width = 2)
```

**If you want to see where the level used to be, it is not a level.** A value
whose past matters is a column, and a column is a plot. Use `style = "step"` so
that the picture says "it was this, then it became that" rather than sloping
between readings that never happened:

```
// The same session open, drawn as a column, so every past session's open is
// visible at the bars it applied to.
plot(sessionOpen, "Session open", fade(aqua, 25), width = 2, style = "step")
```

Both forms are right; they answer different questions. The level answers "where
is it now", from anywhere on the chart. The step plot answers "where was it
then". A study that wants both draws both, and pays one plot slot for the
second.

## Choosing between a level, a step plot and a drawing

| | `level` | `plot(..., style = "step")` | `draw.line` |
|---|---|---|---|
| Extent | The whole pane, edge to edge | The bars the value existed on | Between two anchored points, optionally extended |
| How many | Fixed at compile time, one per call | Fixed at compile time, one per call | As many as the script creates, at any time |
| Past positions | Not shown | Shown | Shown, and each one persists until deleted |
| Cost | None | One plot slot | Memory per live object |
| Readable back | No | Yes, with `[]` | No |
| Good for | A threshold, today's reference prices, a zero line | A reference whose history matters | A trendline, a zone, a channel between two pivots |

The tie-breaker, in one sentence each: **a threshold is a level, a reference
with a history is a step plot, a geometric object between two points in time is
a drawing.**

## Fixing a pane's range

```
study("RSI", precision = 2, range = [0, 100])
```

`range` takes `[min, max]` and pins the study pane's scale. It is a study
option, so it applies to the whole pane, and its value must be a compile-time
constant: literals, arithmetic over literals, or an `input()`.

Why pin it at all? Because an axis that rescales turns a bounded reading into an
unbounded shape. On an unpinned pane, an oscillator that spent a month between
45 and 55 fills the pane with a dramatic-looking wave, and the 70 line is off
the top of the screen. The reading is "nothing happened", and the picture says
"a great deal happened". Pinning the range makes a quiet month look quiet, which
is the entire value of a bounded oscillator.

When to pin, and when not to:

| Reading | Pin it? | Why |
|---|---|---|
| A 0 to 100 oscillator | Yes, `[0, 100]` | It has real bounds and the thresholds have fixed meaning |
| A -100 to 100 oscillator | Yes | Same, and it puts zero in the middle of the pane |
| A 0 to 1 position within a band | Yes, or a little wider | It has real bounds, and values outside them are themselves the signal |
| A trend strength reading that lives between 10 and 40 | Yes, but pin it to the useful part, not the theoretical one | `[0, 60]` uses the pane; `[0, 100]` wastes half of it |
| A difference of two moving averages | No | It has no bounds, and its scale changes with the instrument |
| Volume, a spread, a premium | No | Same, and the useful scale changes from week to week |
| A percentage change | Usually not | The interesting range depends on the instrument and the interval |

Pinning a range is a promise that values outside it do not need to be read. If
the reading can leave the range and you still want to see it, do not pin it.

A pinned range pairs naturally with levels: the levels give the pane its fixed
landmarks, and the range guarantees those landmarks are always at the same
height.

```
version 1

study("Position in the band", precision = 2, range = [-0.25, 1.25])

len  = input(20,  "Length", min = 2, max = 500)
mult = input(2.0, "Deviations", min = 0.1, max = 10)

// 0 at the lower band, 1 at the upper one. The range is widened a quarter each
// way so that a close outside the band is visible instead of clipped.
p = bbPercent(close, len, mult)

level(1, "Upper band", fade(red, 40))
level(0, "Lower band", fade(lime, 40))
level(0.5, "Basis", fade(gray, 70), style = "dotted")

plot(p, "Position", purple, width = 2)
```

## The price axis

Four things decide what the axis beside a pane says, and it helps to know which
one to reach for.

| Want | Set | Where |
|---|---|---|
| How many decimals | `precision`, 0 to 10 | The declaration, or a plot |
| Whether it reads as a price, a percentage or a volume | `format`, one of `"price"`, `"percent"`, `"volume"` | The declaration, or a plot |
| Which side of the pane a column maps to | `scale`, one of `"right"`, `"left"`, `"none"` | A plot |
| The fixed extent of the scale | `range = [min, max]` | The declaration |

```
study("Relative volume", format = "percent", precision = 1)
study("Traded quantity", format = "volume", precision = 0)
study("Premium", format = "price", precision = 2)
```

Set these on the declaration whenever the whole pane reads the same way, which
is almost always. Setting `precision` or `format` on an individual `plot` sets
the formatting of **the price scale that plot maps to**, not of that one line,
because formatting belongs to an axis and an axis is shared. The consequence is
worth knowing before you hit it: setting either one on a plot drawn over the
price pane reformats the instrument's own axis, and the compiler emits warning
OS8007 when a script does that. What you usually wanted there was a second axis:

```
plot(changePct, "Change, percent", aqua,
     format = "percent", scale = "left", overlay = true)
```

Formatting is display only. `format = "percent"` does not divide anything by a
hundred, and `precision = 2` does not round anything. Use `round(x, 2)` when you
want the value itself changed.

### Labels on the axis

A level carries a `title`, and that title is its label: it is the text the host
shows for that line. Give every level a title even when the height looks
obvious, because a pane with four unlabelled dashed lines is a pane whose author
knew what they meant and whose reader does not.

```
level(70, "Overbought", fade(red, 40))       // labelled
level(70, color = fade(red, 40))             // a line with no explanation
```

A plot's `title` does the same job in the legend, where it appears beside the
column's current value. Between a level's title and a plot's title, every line
in a pane can name itself.

Version 1 has no call that writes arbitrary text onto the price axis. When you
want a caption that follows a value, anchor a label to the newest bar and move
it as new bars arrive:

```
version 1

study("Anchored VWAP with a tag", overlay = true, precision = 2)

v = vwap()

var tag = none

// Only on the newest bar. One label, moved forward, rather than one label per
// bar. The rollback rule makes this safe on a live chart: the newest bar is
// re-executed on every update and the object set is restored first, so the
// label is moved again rather than duplicated.
if bar.isLast
    if isNone(tag)
        tag = draw.label(time, v, "VWAP " + text(v, 2),
                         color = fade(orange, 25), textColor = black)
    else
        draw.setAt(tag, time, v)
        draw.setText(tag, "VWAP " + text(v, 2))

plot(v, "VWAP", orange, width = 2)
```

That is more work than a level, and it buys something a level cannot give: text
that carries the value, positioned at the right-hand edge where a trader reads
prices.

## Common reference lines

A short catalogue, because these are the ones almost every study wants.

| Line | Written |
|---|---|
| Zero, under a signed oscillator | `level(0, "Zero", fade(gray, 55), style = "solid")` |
| Oscillator thresholds | `level(70, "Overbought", fade(red, 40))` and `level(30, "Oversold", fade(lime, 40))` |
| A midline | `level(50, "Middle", fade(gray, 70), style = "dotted")` |
| Yesterday's high and low | `level(req.timeframe("1D", high), "Previous day high", fade(aqua, 25))` |
| Today's open, held in a `var` | Capture on `session.isFirstBar`, then `level(sessionOpen, ...)` |
| A price the user types | `myLine = input(0.0, "My line")` then `level(myLine, "My line", fade(aqua, 25))` |
| A position's average price | `level(pos.isFlat ? none : pos.avgPrice, "Entry", fade(silver, 30))` |
| A stop a fixed distance under the entry | `level(pos.isFlat ? none : pos.avgPrice - mult * atr(14), "Stop", fade(red, 30))` |

`input()` is written on its own line rather than nested inside the `level` call,
because an input declares a row of the settings dialog and a reader scanning a
file wants every one of those rows in one block at the top.

The last two rows are levels whose price is absent some of the time, which is
exactly right: an entry line has no meaning while the strategy is flat, and an
absent price draws no line.

## Common mistakes

| Mistake | What happens | Fix |
|---|---|---|
| Wrapping `level` in an `if` | OS3006 | Give the price `none` on the bars where there is none |
| A level whose price is only set on one bar | Usually nothing is drawn, because the last executed bar decides | Hold the value in a `var` |
| Expecting to scroll back and see where the level was | A level has no history | Use `plot(..., style = "step")` for that |
| Trying to `fill` between a plot and a level | A level is not a plot and cannot be one end of a fill | Plot the constant, at `fade(colour, 100)` if it should not show |
| Pinning a range on an unbounded reading | The line leaves the pane and you cannot see it | Only pin a reading with real bounds |
| `precision` or `format` on an overlay plot | Warning OS8007, and the instrument's own axis is reformatted | Put the plot on `scale = "left"`, or set it on the declaration of a study with its own pane |
| Solid reference lines as heavy as the data | The reader cannot tell the reference from the reading | Dashed or dotted, faded, thin |
| Levels with no titles | Nobody else can read the pane | Title every one |
